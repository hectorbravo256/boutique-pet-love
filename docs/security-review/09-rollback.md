# Reversal procedure — draft
Do not execute in production. The draft SQL files end in ROLLBACK. For a future committed migration, generate exact inverse DDL from the pre-change metadata export and schema-only dump; rehearse on an isolated clone. Restore original function definitions and owners, policies (including permissive/restrictive flags), RLS and FORCE flags, view options, object and column ACLs, default ACLs and schema grants. Remove new authorization objects only after removing dependent policies and functions. Do not reset sequence values or restore historical business rows. Coordinate application rollback with database changes; restoring insecure permissions is an emergency measure only, with affected public endpoints disabled. Exact executable inverse remains pending until the forward migration is finalized. No backup has been performed by this document.
