# Catalog access separation — proposed design
Keep existing tables and foreign keys. Public reads use explicit projections with column SELECT grants for both anon and authenticated. Existing active-row RLS remains. Admin-only columns are accessed through narrow guarded RPCs or authenticated server endpoints, not table-wide SELECT. Do not expose service credentials to browser.
First pilot: barcode label listing, currently BarcodeLabelsPage.jsx line 23 reads nested sku/barcode. Candidate RPC returns equivalent JSON, includes inactive products for admin, uses private.is_admin(), explicit schema references, empty search_path, no dynamic SQL. Admin UI adaptation is phase D, not authorized in C.
Public query replacements (proposed, not applied):
Product.jsx: id,name,description,category,image,active,discount_active,discount_percent,discount_start,discount_end,featured,slug,meta_title,meta_description,seo_keywords,new_collection,best_seller,luxury,exclusive,gender,product_variants(id,product_id,size,price,stock),product_images(id,product_id,url,sort_order)
Category.jsx: same product projection; category id,name,slug,image,active,sort_order,featured_image,seo_title,seo_description,seo_text.
Checkout.jsx settings: id,enabled,timezone,cutoff,pickup_weekdays,preparation_days. Coupon wildcard must be replaced by server validation, not public projection.
Before revoking authenticated table SELECT, migrate every admin reader and writer requiring hidden columns, including views, barcode lookup, stock minimum, variant edits, insert/update returning *, and inventory reports. Invoker views may need redesigned guarded RPCs. Column write permissions and row policies are separate.
No application edits or DB changes. Pilot does not solve all admin consumers. Test anon/nonadmin denial, admin inactive products, empty variants, ordering, exact JSON contract, label generation and public route regression. Existing internal SKU is not needed for Google Shopping identifiers.
